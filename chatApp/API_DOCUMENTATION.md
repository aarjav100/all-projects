# ChatApp API Documentation

This document describes the Firebase backend structure and API patterns used in the ChatApp Android application.

## Firebase Services Used

- **Firebase Authentication**: User authentication and management
- **Cloud Firestore**: Real-time database for messages and user data
- **Firebase Storage**: File storage for images and media
- **Firebase Cloud Messaging (FCM)**: Push notifications

## Database Structure

### Collections Overview

```
/users/{userId}
/messages/{messageId}
/chats/{chatId}
```

## Users Collection

**Path**: `/users/{userId}`

### User Document Structure

```json
{
  "uid": "string",
  "name": "string",
  "email": "string",
  "profileImageUrl": "string",
  "isOnline": "boolean",
  "lastSeen": "timestamp",
  "fcmToken": "string"
}
```

### Fields Description

| Field | Type | Description |
|-------|------|-------------|
| `uid` | String | Unique user identifier from Firebase Auth |
| `name` | String | User's display name |
| `email` | String | User's email address |
| `profileImageUrl` | String | URL to user's profile image in Firebase Storage |
| `isOnline` | Boolean | Current online status |
| `lastSeen` | Timestamp | Last time user was active |
| `fcmToken` | String | Firebase Cloud Messaging token for notifications |

## Chats Collection

**Path**: `/chats/{chatId}`

### Chat Document Structure

```json
{
  "chatId": "string",
  "participants": ["string", "string"],
  "lastMessage": "string",
  "lastMessageTime": "timestamp",
  "lastMessageSenderId": "string",
  "unreadCount": "number"
}
```

### Fields Description

| Field | Type | Description |
|-------|------|-------------|
| `chatId` | String | Unique chat identifier (combination of participant UIDs) |
| `participants` | Array | Array of participant UIDs |
| `lastMessage` | String | Preview of the last message |
| `lastMessageTime` | Timestamp | When the last message was sent |
| `lastMessageSenderId` | String | UID of who sent the last message |
| `unreadCount` | Number | Number of unread messages |

### Chat ID Generation

Chat IDs are generated by combining participant UIDs in alphabetical order:
```kotlin
val chatId = if (currentUserId < receiverId) {
    "${currentUserId}_${receiverId}"
} else {
    "${receiverId}_${currentUserId}"
}
```

## Security Rules

### Firestore Security Rules

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Users can read/write their own document and read others
    match /users/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
      allow read: if request.auth != null;
    }
    
    // Messages can be accessed by sender and receiver
    match /messages/{messageId} {
      allow read, write: if request.auth != null && 
        (request.auth.uid == resource.data.senderId || 
         request.auth.uid == resource.data.receiverId);
    }
    
    // Chats can be accessed by participants
    match /chats/{chatId} {
      allow read, write: if request.auth != null && 
        request.auth.uid in resource.data.participants;
    }
  }
}
```

### Storage Security Rules

```javascript
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /chat_images/{userId}/{allPaths=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
    
    match /profile_images/{userId}/{allPaths=**} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

## Error Handling

### Common Error Scenarios

1. **Network Errors**: Handle offline scenarios gracefully
2. **Permission Denied**: Ensure proper authentication and security rules
3. **Storage Quota**: Handle storage limit exceeded errors
4. **Invalid Data**: Validate input before sending to Firebase

### Error Handling Pattern

```kotlin
service.performOperation()
    .onSuccess { result ->
        // Handle success
    }
    .onFailure { exception ->
        when (exception) {
            is FirebaseAuthException -> // Handle auth errors
            is FirebaseFirestoreException -> // Handle database errors
            is StorageException -> // Handle storage errors
            else -> // Handle generic errors
        }
    }
```

## Performance Considerations

### Query Optimization

1. **Indexing**: Ensure proper Firestore indexes for queries
2. **Pagination**: Implement pagination for large message lists
3. **Caching**: Use Firestore offline persistence
4. **Image Optimization**: Compress images before upload

### Best Practices

1. **Batch Operations**: Use batch writes for multiple updates
2. **Listener Management**: Properly remove listeners to prevent memory leaks
3. **Data Validation**: Validate data on client and server side
4. **Security**: Never trust client-side data, enforce rules server-side

## Rate Limits and Quotas

### Firestore Limits
- **Writes**: 1 write per second per document
- **Reads**: No limit on reads
- **Document Size**: Maximum 1 MB per document

### Storage Limits
- **File Size**: Maximum 32 MB per file
- **Total Storage**: Depends on Firebase plan

### FCM Limits
- **Message Rate**: 1000 messages per minute per project
- **Payload Size**: Maximum 4 KB per message
